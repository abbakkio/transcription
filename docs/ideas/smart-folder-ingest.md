# Умный пакетный импорт папок и смешанных файлов (Smart Folder & Batch Ingestion)

## 1. Problem Statement
**Как мы можем позволить пользователю просто перетащить в приложение любую папку с файлами (диктофонные записи вперемешку с фото, PDF-заметками и подкаталогами) и мгновенно получить чистую, готовую к транскрибации очередь аудиозаписей без ручной сортировки?**

---

## 2. Recommended Direction: "Zero-Friction Drop & Triage"

Выбранное направление — **бесшовный умный шлюз с мягким отчётом**:
1. **Рекурсивный обход каталогов**:
   Использование HTML5 `webkitGetAsEntry()` с циклическим вызовом `readEntries()` для безопасного чтения папок любой глубины вложенности (включая каталоги с более чем 100 файлами).
2. **Интеллектуальная фильтрация мусора**:
   Система на лету пропускает неаудио-файлы (`.jpg`, `.png`, `.pdf`, `.docx`, системные `.DS_Store` и `Thumbs.db`), извлекая только целевые аудиоформаты (`.mp3`, `.wav`, `.m4a`, `.ogg`, `.flac`, `.aac`).
3. **Прозрачная обратная связь (Non-Intrusive Feedback)**:
   Вместо ошибок или блокирующих окон приложение показывает компактный toast/индикатор:  
   *«Добавлено 8 аудиозаписей из папки "Интервью_Астана" (пропущено 5 неаудио файлов)»*.
4. **Ленивое управление памятью**:
   Предотвращение падения вкладки браузера при загрузке больших папок — сохранение ссылок на нативные объекты `File`, а `URL.createObjectURL` создаётся только для активного трека или при запуске очереди.

---

## 3. Key Assumptions to Validate

- [ ] **Ограничение глубины и объёма**: Предполагаем, что ограничение рекурсии (максимум 5 уровней вложенности) и лимит на пакет (максимум 100 аудиофайлов за один раз) защитит браузер от зависания, если пользователь случайно перетащит системный диск или тяжелую папку проекта.
- [ ] **Понятность фильтрации**: Пользователи ожидают, что картинки и PDF будут просто проигнорированы, и им достаточно короткого информационного уведомления без необходимости подтверждать каждый шаг.
- [ ] **Кроссбраузерность `webkitGetAsEntry`**: API `webkitGetAsEntry` поддерживается во всех актуальных версиях Chrome, Safari, Firefox и Edge, но требует полифилла/фолбэка на стандартный `e.dataTransfer.files`, если браузер устарел.

---

## 4. MVP Scope

### Входит в MVP:
- **Утилита рекурсивного сканирования (`src/utils/folderScanner.ts`)**:
  - Чтение `DataTransferItemList` через `webkitGetAsEntry()`.
  - Циклический обход `FileSystemDirectoryReader.readEntries()` для снятия 100-файлового лимита браузера.
  - Фильтрация по расширениям и MIME-типам (`audio/*`, `.mp3`, `.wav`, `.m4a`, `.ogg`, `.flac`, `.aac`).
- **Интеграция в обе зоны загрузки**:
  - `CompactDropZone.tsx` на главном экране.
  - `BatchDropzoneModal.tsx` в модальном окне загрузки.
- **Информационный статус в UI**:
  - Отображение количества найденных аудиофайлов и пропущенных неаудио-объектов.
- **Защитные лимиты**:
  - Защита от зависания: лимит сканирования до 200 файлов и лимит размера отдельного аудио до 250 МБ.

---

## 5. Not Doing (and Why)

- ❌ **Извлечение аудиодорожек из видео (`.mp4`, `.mov`, `.mkv`) на клиенте**:  
  *Причина:* Требует тяжелых библиотек вроде FFmpeg.wasm (размер бандла 25–35 МБ), что перегрузит легковесный интерфейс. Лучше оставить для серверной обработки.
- ❌ **Сложный древовидный проводник по папкам (Folder Tree Explorer)**:  
  *Причина:* Перегружает минималистичный интерфейс. Список файлов должен оставаться плоской, чистой очередью задач.
- ❌ **Парсинг текста из PDF-документов в качестве словаря терминов**:  
  *Причина:* Интересная идея для будущих версий, но усложняет текущую задачу быстрой и простой транскрибации звука.
