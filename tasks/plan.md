# Implementation Plan: Smart Folder & Batch Ingestion

## Overview
Реализация умного шлюза пакетного импорта, позволяющего перетаскивать целые папки с аудиозаписями (включая вложенные подпапки) и пачки смешанных файлов. Система автоматически рекурсивно обходит каталоги через `webkitGetAsEntry()`, собирает все поддерживаемые аудиозаписи (`.mp3`, `.wav`, `.m4a`, `.ogg`, `.flac`, `.aac`), молча отсеивает неаудио-файлы (`.pdf`, `.jpg`, `.png`, `.DS_Store`), защищает память от переполнения и выводит лаконичный отчёт пользователю.

## Architecture Decisions
- **`src/utils/folderScanner.ts`**: Ядро асинхронного сканирования. Обходит `DataTransferItem` через `webkitGetAsEntry()`. Решает ограничение браузеров на возврат максимум 100 записей за раз через циклический вызов `reader.readEntries()`. Включает защитные лимиты: глубина вложенности не более 5 уровней, максимум 200 сканируемых файлов.
- **Информационный статус (Feedback Toast)**: Ненавязчивый анимированный тост на главном экране и информационная строка в модальном окне, сообщающая: *«Добавлено N аудиозаписей (пропущено M неаудио файлов)»*.
- **Сохранение плоской структуры с префиксом папки**: Для файлов из подпапок имя дополняется именем родительской папки (например, `Интервью/спикер_1.mp3`), предотвращая путаницу при одинаковых именах.
- **Память и лимиты**: Размер одного аудиофайла ограничен 250 МБ; Blob URL создаются только для активного воспроизводимого трека.

## Risks and Mitigations
| Риск | Влияние | Стратегия устранения |
|---|---|---|
| Пользователь перетащил папку с тысячами файлов (например, `node_modules`) | Высокое (зависание вкладки) | Жесткий лимит `MAX_FILES = 200` и `MAX_DEPTH = 5`. При превышении сканирование прерывается с предупреждением. |
| Ограничение браузера на 100 файлов в `readEntries` | Среднее (потеря файлов после 100-го) | Циклический опрос `readEntries` до возврата пустого массива. |
| Браузеры без поддержки `webkitGetAsEntry` | Низкое | Фолбэк на стандартный `e.dataTransfer.files`. |
